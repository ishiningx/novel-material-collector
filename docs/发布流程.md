# 发布流程指南

> 本文档记录小说素材收集项目从「本地改完代码」到「Gitee 用户能下载到新版」的完整流水线操作手册。

---

## 一、整体链路

```
本地 npm run release <版本号>
        │
        │  自动 commit + 打 tag + push
        ▼
GitHub 仓库 (ishiningx/novel-material-collector)
        │
        │  tag push 触发 "Build and Release"
        ▼
GitHub Actions 并行构建
  ├── macOS Apple Silicon (aarch64-apple-darwin)
  ├── macOS Intel       (x86_64-apple-darwin)
  └── Windows           (windows-latest)
        │
        │  产物直传 GitHub Release（releaseDraft: false）
        ▼
GitHub Release 创建完成
        │
        │  workflow_run 串行触发 "Sync to Gitee"
        ▼
Sync to Gitee
  ├── ff-merge main 到 Gitee（同步 latest.json）
  ├── 下载 GH Release 资产
  └── 创建 Gitee Release + 上传产物
        │
        ▼
用户打开应用 → 点「检查更新」→ 读 Gitee latest.json → 跳转 Gitee Release 下载
```

## 二、发版三步走

### 第 1 步：本地跑发布脚本

```bash
cd /Users/shine/Qoder/novel-material-collector
npm run release 1.1.6   # 改成你要发的版本号
```

脚本会依次执行：

| 阶段 | 动作 |
|---|---|
| 1 | 校验：工作区干净、分支为 `main`、tag 未存在、版本号格式 `x.y.z` |
| 2 | 第 1 次确认：`确认发布 v1.1.6? (y/N)` |
| 3 | 交互式读取 releaseNotes（多行；连续两次空行或单独一行 `END` 结束） |
| 4 | 第 2 次确认：`说明是否 OK? (y/N)` |
| 5 | 自动同步 4 处版本号（见下方列表）→ `git add` → commit → 打 tag |
| 6 | 第 3 次确认：`push 到 origin 并触发 CI? (y/N)` |
| 7 | `git push origin main` + `git push origin v1.1.6` |

**版本号会被同步到的 4 处**（一处漏了都会出问题）：

1. `package.json` 的 `version`
2. `src-tauri/tauri.conf.json` 的 `version` — **UI 上显示的版本号来自这里**
3. `src-tauri/Cargo.toml` 的 `version`
4. `latest.json` 的 `version`（同时写入 `releaseDate` 和 `releaseNotes`）

### 第 2 步：盯 GitHub Actions

- **进度页**：https://github.com/ishiningx/novel-material-collector/actions
- 典型耗时：**15–25 分钟**（三个平台并行，Rust 编译最慢）
- 跑完后会看到 GitHub Release 自动出现在：
  - https://github.com/ishiningx/novel-material-collector/releases

### 第 3 步：验证 Gitee 同步

Sync to Gitee workflow 会在 Build 成功后**自动串行触发**，不需要你干预。跑完后验证：

- **Gitee Release 页面**：https://gitee.com/ishiningx/novel-material-collector/releases
  - 看是否有新版本号对应的 Release
  - 看资产列表（应包含 macOS aarch64 dmg、macOS x64 dmg、Windows exe/msi）
- **latest.json 同步**：https://gitee.com/ishiningx/novel-material-collector/raw/main/latest.json
  - `version` 字段应为新版本号
  - `releaseNotes` 应为你刚才输入的内容

- **应用内检查更新**：打开旧版应用，点左下角 footer 的「检查更新」，应提示「发现新版本」并能跳转到 Gitee Release 页

## 三、常见问题排查

### Q1：`git push` 报 `Error in the HTTP2 framing layer`

GitHub 在中国大陆的常见抖动。**不要改全局 git config**，用单次命令级 override：

```bash
git -c http.version=HTTP/1.1 push origin main
git -c http.version=HTTP/1.1 push origin v1.1.6
```

一劳永逸方案（选一个）：

```bash
# 方案 A：只对本仓库启用 HTTP/1.1
git config http.version HTTP/1.1

# 方案 B：改用 SSH remote（推荐）
git remote set-url origin git@github.com:ishiningx/novel-material-collector.git
```

### Q2：UI 显示的版本号不对

Tauri 2 的 `getVersion()` API **只读 `src-tauri/tauri.conf.json`**，不读 `Cargo.toml` 也不读 `package.json`。release 脚本已经同步 4 处版本号，如果显示不对先确认 `tauri.conf.json` 是否同步。

### Q3：点「检查更新」提示「检查失败」

排查顺序：

1. **URL 正确**：`src/services/updater.ts` 里 Gitee owner 是否为 `ishiningx`（曾经错拼为 `shine100`）
2. **capabilities 权限**：`src-tauri/capabilities/default.json` 里 `http:default` 的 `allow` 必须包含：
   - `https://gitee.com/*`
   - `https://*.gitee.com/*`
   - `https://raw.giteeusercontent.com/*`（Gitee raw 会 302 到此域）
3. **http 插件必须注册**：`src-tauri/src/lib.rs` 里要有 `.plugin(tauri_plugin_http::init())`
4. **不要用原生 fetch**：dev 模式下 webview 跑在 localhost:1420，会被 CORS 拦。必须用 `@tauri-apps/plugin-http` 的 `tauriFetch`（走 Rust 侧）

### Q4：GitHub Actions 跑 Build 挂了

- **Tauri 插件版本不一致**：日志里 `Found version mismatched Tauri packages`，例：`tauri-plugin-fs (v2.5.0) : @tauri-apps/plugin-fs (v2.4.5)`
  - 修复：`npm install @tauri-apps/plugin-fs@latest`，再 commit，再跑一次 release（版本号递增一位）
- **Rust 编译错误**：本地 `cd src-tauri && cargo build` 先复现
- **Mac Intel 构建首次可能慢**：第一次加 `x86_64-apple-darwin` target 会下载 rust toolchain，耐心等

### Q5：Sync to Gitee 没触发或失败

- **有没有触发**：workflow_run 依赖 Build 成功。Build 失败 → Sync 不会跑。进 GH Actions 看 Build 是否完整 success
- **Gitee 推送失败**：Secrets 里要配 `GITEE_TOKEN`（Gitee OpenAPI token）、`GITEE_USERNAME`、`GITEE_REPO`
- **手动重跑**：Actions 页面进入 `Sync to Gitee` → `Run workflow` → 填 tag 名（如 `v1.1.6`）

## 四、回滚方法

### 情况 A：push 前发现问题（commit + tag 还在本地）

```bash
git tag -d v1.1.6           # 删本地 tag
git reset --hard HEAD~1     # 撤销 release commit
```

然后修好问题再 `npm run release 1.1.6`。

### 情况 B：已经 push 到 GitHub 但 CI 还没跑完

1. 先取消 Actions 里正在跑的 workflow
2. 删远端 tag 和分支状态：
   ```bash
   git push origin :refs/tags/v1.1.6   # 删远端 tag
   git reset --hard HEAD~1
   git -c http.version=HTTP/1.1 push --force origin main
   ```
   （⚠️ `--force` 危险，确认只有自己在 push）

### 情况 C：已经发布完，用户已经下载

**不要撤版本号**，直接发下一个补丁版（如 `1.1.6` 有问题就发 `1.1.7`）。硬撤会导致用户的自动更新检测逻辑出现跳版本的怪情况。

## 五、文件清单（与发布相关）

| 文件 | 作用 |
|---|---|
| `scripts/release.mjs` | 一键发布脚本（本地触发） |
| `.github/workflows/build.yml` | GitHub Actions：三平台构建 + Release |
| `.github/workflows/sync-to-gitee.yml` | GitHub Actions：同步 Gitee（workflow_run 串行） |
| `latest.json` | 更新元数据文件（版本号 / 发布说明 / 下载页 URL） |
| `src/services/updater.ts` | 应用内「检查更新」逻辑（读 Gitee latest.json） |
| `src-tauri/capabilities/default.json` | Tauri 权限配置（http / opener 白名单） |
| `src-tauri/tauri.conf.json` | **UI 显示版本号的唯一来源** |

---

## 六、Secrets 清单（GitHub 仓库 Settings → Secrets）

| 名称 | 用途 |
|---|---|
| `GITEE_TOKEN` | Gitee OpenAPI token，用于创建 Release、上传资产 |
| `GITEE_USERNAME` | Gitee 用户名（`ishiningx`） |
| `GITEE_REPO` | Gitee 仓库名（`novel-material-collector`） |
| `GITEE_GIT_TOKEN` | 用于 git push 到 Gitee（同步 main 分支） |
